\section{Methodology}
\label{sec:methodology}

The methodology describes the datasets, preprocessing, model configurations, experimental procedure, and evaluation methods used to compare YOLOv8 and LLaVA 1.6 for housing inspection image analysis. Both models were evaluated using the same harmonized dataset, inspection categories, and evaluation protocol to enable a controlled comparison.

\subsection{Data Sources}
\label{subsec:data_sources}

The experimental setup is based on publicly available datasets obtained through Roboflow, which provide annotated examples of damage related visual patterns \cite{noauthor_roboflow_nodate}.

These datasets differ in annotation structure, label definitions, visual characteristics, image quality, and class distributions. They are used as heterogeneous source material for constructing a unified inspection task. 

To enable comparison of the models the original labels are harmonized into a shared set of inspection categories. Figure 1 illustrates the distribution of labels before and figure 2 demonstrates it after harmonization. The heterogeneous datasets contain natural variation in image quality, lighting conditions, and viewpoints, allowing limited observations regarding model generalization.

\subsection{Inspection Categories}
\label{subsec:inspection_categories}

The shared label scheme consists of six inspection relevant categories:

\begin{itemize}
    \item \textbf{Damage}: visible damage to building components, such as holes, broken materials, chipped surfaces, or impact damage
    \item \textbf{Crack}: visible linear fractures or splits in walls, ceilings, floors, tiles, or other structural surfaces
    \item \textbf{Mold}: visible fungal growth, moisture stains, or mildew caused by damp conditions
    \item \textbf{Asbestos}: visible asbestos-containing materials or asbestos-related surface markings identified in the reference dataset
    \item \textbf{Wear}: gradual deterioration caused by normal use, such as scratches, scuff marks, discoloration, or surface aging
    \item \textbf{No damage}: no visible inspection-relevant defects or deterioration present.
\end{itemize}

This schema is derived from the application domain rather than from the original dataset labels. All source labels are mapped to these categories where possible. Labels that do not align clearly are excluded or treated cautiously during interpretation.


\subsection{Dataset Harmonization}
\label{subsec:dataset_harmonization}

The publicly available Roboflow datasets exhibit substantial heterogeneity in annotation structure, label definitions, image composition, and class distributions. Some datasets contain only positive examples, such as the crack detection dataset, while others include both damaged and undamaged images. In addition, identical visual phenomena are often described using different labels across datasets. For example, structural defects may be labeled as \textit{crack}, \textit{damage}, \textit{Amber}, or \textit{Red}, while mold and asbestos datasets use entirely different category schemes.

To enable meaningful comparison, all datasets are harmonized into a shared inspection oriented label framework consisting of the categories \textit{Damage}, \textit{Crack}, \textit{Wear}, \textit{Mold}, \textit{Asbestos}, and \textit{No Damage}. This harmonization process reduces label inconsistency and ensures that both YOLOv8 and LLaVA are evaluated on the same conceptual inspection task. The complete mapping procedure is shown in Table~\ref{tab:mapping}.

To verify the harmonization procedure, a sample of images from each dataset was manually inspected after label mapping. This validation step was used to confirm that the original labels were consistently assigned to the appropriate harmonized inspection categories. Figure~\ref{fig:beforeharm} and Figure~\ref{fig:afterharm} illustrates the label distribution before and after harmonization, demonstrating how heterogeneous dataset specific labels were transformed into a unified inspection category framework.

\subsection{Pipeline Model}
\label{subsec:pipeline_model}

The pipeline model operationalizes the comparison framework by ensuring that both models are evaluated using the same data preparation procedure, inspection categories, and evaluation protocol. The experimental setup follows an organized and unified pipeline that enables a controlled comparison between YOLOv8 and LLaVA 1.6. As shown in Figure~\ref{fig:pipeline}, the harmonized dataset is processed in parallel, where YOLOv8 produces object detections, LLaVA 1.6 generates textual descriptions from the same test images. Both outputs are converted into a shared image level representation through a rule based harmonization step before being evaluated using identical metrics and qualitative error analysis. This unified pipeline ensures a fair comparison by maintaining consistent data processing and evaluation across both models.

\subsection{Experimental Setup}
\label{subsec:experimental_setup}

The experimental setup was designed to ensure a fair comparison between YOLOv8 and LLaVA 1.6. All public datasets were harmonized into a shared inspection category framework consisting of Damage, Wear, Mold, Asbestos, and No Damage.

\subsubsection{Data Preparation}

The harmonized dataset was divided into training, validation, and test subsets using a stratified split (ensures that the proportion of classes in train and test sets match the original dataset)\cite{jocher_ultralytics_2023}. A ratio of 70\% training, 15\% validation, and 15\% testing was applied. All annotations were represented as bounding boxes. This process ensures that class distributions are preserved across splits.

The datasets are first processed by mapping their original labels to the shared inspection categories. Where necessary, labels are merged or reinterpreted to ensure consistency. The resulting dataset is then formatted for model input.

\subsubsection{YOLOv8 configuration}

YOLOv8 was trained using the harmonized training dataset and initialized with pretrained COCO weights\cite{jocher_ultralytics_2023}. Training is performed with fixed hyper parameters to ensure reproducibility and comparability. The model was trained with 75 epochs using a fixed random seed 42 to support reproducibility. Hyper parameters were kept constant throughout the experiments, These include the number of epochs 75, batch size, input resolution, learning rate, and detection thresholds. The final model is selected based on validation performance and evaluated on the test set. YOLOv8 predictions were evaluated using object detection metrics. 

Figure~\ref{fig:pipeline} provides an overview of the experimental workflow.

\subsubsection{LLaVA Configuration}

LLaVA 1.6 (LLaVA-v1.6-Mistral-7B) was evaluated using two prompting strategies\cite{liu_visual_2023}. The first strategy consisted of a zero shot baseline, in which the model received a fixed system prompt and user prompt without task specific examples. The second strategy employed a rule guided decision prompt that incorporated explicit inspection rules, class definitions, tie breaking rules, structured JSON output, and a more robust output parsing procedure. The second prompting strategy was developed following qualitative analysis of the zero shot baseline, which revealed recurring classification and output parsing errors.

For both configurations, the same test images and prompt templates were used throughout the experiments to ensure consistency. The model was evaluated without task specific fine tuning, allowing its performance to be assessed in a prompt based setting. Inference was performed deterministically using \texttt{do\_sample=False}, and each response was required to return a structured JSON object containing a single inspection category and a short explanation (for enabling qualitative error analysis when necessary) . 

The generated JSON responses were subsequently converted into the harmonized inspection categories using a rule based mapping procedure before quantitative evaluation. The complete prompts are provided in Appendix~\ref{appendix:llava}

\subsubsection{Output harmonization}

YOLOv8 produces bounding boxes with class predictions, while LLaVA produces textual descriptions. To enable comparison, both outputs are mapped to the shared inspection categories.

For YOLOv8, detections below a confidence threshold are removed, and remaining detections are aggregated to image level category predictions.

For LLaVA, the generated JSON responses were converted into inspection categories using a rule based parsing procedure. During preliminary experiments, qualitative inspection revealed that simple keyword matching incorrectly interpreted negated statements such as "no asbestos detected" as positive predictions. The parser was therefore refined to recognise negated expressions before assigning the final inspection category.

This harmonization step is central to the methodology, as it enables direct comparison between fundamentally different output formats.

\subsection{Evaluation Metrics}
\label{subsec:evaluation_metrics}

The evaluation metrics were selected to assess both detection performance and category level classification performance. Because YOLOv8 and LLaVA produce different output formats, two levels of evaluation are used.

For YOLOv8, object detection performance is measured using Precision, Recall, F1 score, and mean Average Precision (mAP) \cite{redmon_you_2016}. Precision measures the proportion of predicted detections that are correct, while Recall measures the proportion of ground truth defects that are successfully detected. The F1 score provides a balanced measure of Precision and Recall.

Mean Average Precision (mAP) is the primary object detection metric and evaluates both localization and classification performance. A prediction is considered correct when the predicted class matches the ground truth class and the Intersection over Union (IoU) exceeds a predefined threshold. The mAP score is calculated as the mean of the Average Precision values across all categories.

For comparison between YOLOv8 and LLaVA, outputs are additionally evaluated at the inspection category level. YOLOv8 bounding box predictions and LLaVA textual outputs are converted to the shared inspection categories described in Section~\ref{subsec:dataset_harmonization}. Category level performance is then measured using Accuracy, Precision, Recall, and F1 score.

Confusion matrices are generated for both models to support interpretation of classification errors and category specific failure modes. This dual evaluation strategy enables both object detection assessment and direct comparison between the supervised detector and the multi modal foundation model.

\subsection{Reproducibility}

Experiments use fixed seeds where applicable to support reproducibility. Dataset preprocessing, harmonization procedures, inference settings, and evaluation pipelines are version controlled through GitHub. Public datasets and experimental configurations are documented to enable replication.

\subsection{Qualitative and Error Analysis}

To complement the quantitative evaluation, qualitative analysis was performed throughout model development by manually inspecting representative predictions and failure cases for both models.

During the initial dataset construction, all images were merged before performing a global train validation test split. Inspection of the resulting subsets revealed that multiple minority categories, particularly mold, asbestos, and wear, were underrepresented in the training set while appearing more frequently in the validation and test sets. To address this issue, the splitting procedure was modified to perform stratified splits within each source dataset before merging the subsets. This ensured a more balanced class distribution across the training, validation, and test sets and resulted in improved model performance.

Initial experiments showed that smaller defects, particularly fine cracks and asbestos markings, were frequently missed at an input resolution of 640 × 640 pixels. Based on these observations and evidence from medical imaging literature indicating that higher image resolutions can improve the detection of small visual abnormalities, the input resolution was increased to 1024 × 1024 pixels \cite{litjens_deep_2017,rana_yolo_2025,kamraoui_longitudinal_2022}.

For LLaVA, qualitative analysis focused on the generated textual responses, parsed JSON outputs, and the final inspection labels produced by the rule based output mapping. This analysis showed that several classification errors originated from the output conversion rather than from the language model itself. For example, responses such as "no asbestos detected" were initially mapped to the asbestos category because the parser matched keywords without considering negation. Following these observations, the prompt and output conversion procedure were refined to return a single inspection category, resulting in more reliable classification performance. These qualitative observations complemented the quantitative evaluation by identifying failure modes that were not apparent from performance metrics alone. These observations were used to refine the experimental pipeline before the final quantitative evaluation presented in Chapter~\ref{sec:results}.

\subsection{Validity, Reliability, and Reproducibility}
\label{subsec:validity_reliability}

Internal validity is ensured by evaluating both models under identical conditions, using fixed prompts and consistent training settings. Construct validity is supported by aligning all data and outputs to inspection relevant categories.

Internal validity is supported by evaluating both models on the same harmonized dataset, using identical inspection categories, shared evaluation metrics, and consistent preprocessing procedures. Construct validity is supported by aligning all datasets and model outputs to a common inspection category framework, ensuring that both models address the same inspection task.

\subsection{Ethical Considerations}
\label{subsec:ethical_considerations}

The experiments are conducted on publicly available datasets in a controlled research setting. The study is intended as decision support research and does not replace human inspection judgment.
